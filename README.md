# Лавка приключенца

Полностью локальная браузерная игра о фэнтезийной торговле. TypeScript, Vite, Canvas 2D; без игровых движков и runtime-зависимостей. Все рисунки созданы программно, бесплатные шрифты включены в проект вместе с лицензиями.

## Запуск

Нужен Node.js **20.19+ или 22.12+**.

```sh
npm install
npm run dev
```

Откройте адрес из терминала (обычно http://localhost:5173).

```sh
npm test           # 26 экономических тестов
npm run balance    # 2400 кампаний: 6 стратегий × 400 seed
npm run build      # проверка TypeScript и production-сборка в dist/
npm run preview    # локальный просмотр production-сборки
```

## Быстрые проверки во время разработки

- `npm run check` — экономические тесты и сборка, обычно несколько секунд.
- `npm run test:smoke` — короткий сценарий на телефоне: закупка, изменение цены
  во время продаж, сохранение и пауза. Требуется запущенный `npm run dev`;
  для другой сборки можно передать `TEST_URL`.
- Полные `test:browser`, `test:mobile`, `test:theme` запускаются при изменении
  соответствующих механик или интерфейса. Симуляции баланса нужны при правках экономики.

При обычном push Actions выполняет тесты, сборку и короткий smoke-сценарий.
Полную мобильную матрицу и темы можно выбрать через **Run workflow → full_tests**.
Загрузка Chromium кэшируется. Успешные логи достаточно читать по итоговому статусу;
подробные логи и скриншоты разбираются при сбое или изменении оформления.

## Описания спроса

События и карточки используют одну шкалу; числовой коэффициент игроку не показывается:

| Внутреннее значение | Формулировка |
|---|---|
| Ниже 0,6 | Значительно ниже обычного |
| От 0,6 до 0,9, не включая 0,9 | Ниже обычного |
| От 0,9 до 1,1 включительно | Обычный |
| Выше 1,1, но ниже 2 | Выше обычного |
| От 2 | Значительно выше обычного |

Описание события берётся из фактического спроса этого дня, как и подпись товара.
Проценты изменения рыночных и закупочных цен сохраняются.

## Игра с телефона

На узком экране доступны три раздела в нижней панели: **Лавка**, **Товары** и
**Развитие**. Товары показаны карточками: закупка, рыночная цена, остаток,
собственная цена и маржа видны без горизонтальной прокрутки. Кнопки **− / +**
меняют цену на одну монету; цену также можно ввести с цифровой клавиатуры.

Касса и текущий день закреплены сверху, а открытие лавки и пауза — снизу.
После открытия автоматически показываются покупатели, после окончания дня —
отчёт, а следующий день начинается с раздела товаров. Событие дня открывается
нажатием на плашку под кассой. Поддерживаются портретный и альбомный режимы,
системные безопасные области экрана и переход обратно к настольной вёрстке.

## Светлая и тёмная тема

Кнопка с луной или солнцем в верхней панели переключает оформление. При первом
открытии используется системная тема устройства; ручной выбор сохраняется
отдельно от игрового прогресса и применяется при следующих открытиях.
Обе темы доступны на телефоне и компьютере, включая цены, отчёты и сцену лавки.
В тёмной теме лавка освещена фонарём, а в окне видны луна и звёзды.

## GitHub Pages

Игра в браузере: **https://kifrip.github.io/adventurers-shop/**.

В **Settings → Pages → Source** выбран **GitHub Actions**.
Workflow `.github/workflows/pages.yml` автоматически запускается при каждом push
в `main`: устанавливает зависимости, выполняет экономические тесты, собирает
`dist/` и публикует его отдельным этапом. При ошибке тестов или сборки публикация
не запускается. Workflow также доступен вручную через **Actions → Deploy game
to GitHub Pages → Run workflow**.

Для обновления достаточно закоммитить исходники и выполнить `git push origin main`.
Сборка хранится в артефакте Actions; каталог `dist/` исключён из Git.
Историческая ветка `gh-pages` больше не участвует в публикации.

Старый адрес `/adventurers-shop/play/` перенаправляет на новый. Сохранения привязаны
к тому же домену и ключу localStorage, поэтому прогресс сохраняется при переходе.

В `vite.config.ts` заданы относительные пути: изображения, шрифты и скрипты
работают под `/adventurers-shop/` и при обычном локальном запуске.
Сохранение остаётся в браузере; серверная часть не нужна.

## Правила

Начальный капитал — 200 золотых. Нужно закончить **седьмой день с 1000 золотых в кассе после аренды**. Стоимость запасов в цель не входит. День торговли длится 90 секунд: 10,5 минут автоматических продаж за кампанию плюс время подготовки. Подготовка не ограничена по времени.

Утром закупайте шесть видов товаров и назначайте целые цены. Следите за событием: девять событий меняют предпочтения, рыночные цены, закупки и посещаемость. В лавку приходят крестьяне, воины и маги со своими бюджетами, предпочтениями и терпимостью к цене. Дорогая цена уменьшает вероятность покупки по логистической кривой. Отказы объясняются в журнале и репликах над посетителями.

Полки вмещают 26 единиц. Дополнительные полки (+14 мест, максимум две), вывеска (+25% гостей) и доброе имя (терпимость к цене) действуют до конца кампании. Они не обязательны для победы. Закупки и улучшения доступны только в подготовке. Цены можно менять и во время продаж, в том числе на паузе: ввод подтверждается Enter, кнопкой «Готово» или уходом из поля. Цена фиксируется для посетителя при его появлении; изменения действуют только для следующих гостей. Торговля автоматическая.

Аренда составляет `12 + 2 × день`: от 14 до 26 золотых. Отрицательная касса после аренды — немедленное банкротство. Открыть пустую лавку можно после предупреждения, поэтому нулевой капитал не блокирует завершение игры. Остатки не портятся и переходят на завтра. Новая игра требует подтверждения замены прогресса.

**Совет:** несколько востребованных видов товаров, умеренная наценка и резерв на аренду надёжнее закупки одного дорогого артефакта. В последний день важна выручка от остатков, а не их оценочная стоимость.

## Учёт денег

- **Касса:** стартовая касса − закупки − улучшения + выручка − аренда.
- **Запасы:** количество каждой партии × её фактическая закупочная цена.
- **Себестоимость продаж:** списывается по FIFO; переоценки старых партий нет.
- **Чистая прибыль:** выручка − себестоимость проданного − аренда − улучшения. Непроданные закупки пока остаются активом.

В вечернем отчёте показаны обе формулы, покупатели, потерянные продажи и остатки всех шести товаров. Финальный экран показывает историю кассы по дням.

## Сохранение и управление

localStorage сохраняет изменения и состояние торговли каждые две секунды; при уходе со страницы выполняется дополнительное сохранение. Закрытая вкладка не приносит выручку. Скрытая вкладка и восстановленная торговля ставятся на паузу. Пробел переключает паузу, Escape закрывает памятку или предупреждение. Повреждённые сохранения отклоняются с уведомлением. Если браузер запрещает localStorage, игра продолжает работать и показывает отсутствие сохранения.

## Проверка в браузере

```sh
npx playwright install chromium
npm run test:browser
npm run test:mobile
npm run test:theme
```

Скрипт использует `/usr/bin/chromium`, если он установлен, иначе Chromium из Playwright. Свой путь можно передать через `CHROMIUM_PATH`. Перед проверкой запустите `npm run dev`. Для другого адреса задайте `TEST_URL`. Проверка проходит покупки, редактирование цен, перезагрузку, паузу, все семь дней через настоящие кнопки и таймер, финальные экраны, новую игру и мобильную вёрстку. Снимки сохраняются в `test-results/`.

Для проверки победного экрана загружается кампания, естественно выигранная адаптивной стратегией через тот же модуль экономики, со всеми семью финансовыми отчётами. Ускоренные часы существуют только в браузерном тесте, в игру отладочные команды не добавлены.

Мобильная проверка использует эмуляцию касаний Chromium на размерах 320×568,
360×740, 390×844, 430×932, 768×1024 и 844×390. Она проверяет закупки,
редактирование цен одним касанием, размеры кнопок, закреплённое управление,
улучшения, сохранение, паузу, отчёт и возврат к настольному виду.
Короткая мобильная проверка запускается в Actions перед каждой публикацией; полная матрица и темы доступны в режиме `full_tests`.
`test:theme` проверяет обе темы, системные настройки, сохранение выбора, контраст
основного текста, вечернюю сцену и сохранность игрового прогресса.

## Устройство проекта

- `src/game.ts` — экономика, события, посетители, фазы, валидация сохранения; не зависит от DOM.
- `src/art.ts` — SVG товаров и анимированная Canvas-сцена.
- `src/main.ts` — интерфейс, управление, таймер и сохранение.
- `src/style.css` и `src/mobile.css` — настольная таблица и мобильные карточки с постоянной панелью управления.
- `tests/` — правила экономики и регрессии.
- `scripts/` — баланс и браузерная проверка.

## Ограничения и следующие шаги

Это одиночный прототип: один слот сохранения, шесть товаров, три профессии, нет звука и ручной расстановки полок. Покупатели анимированы, но не используют поиск пути. Памятка и отчёты доступны как HTML, сама визуальная сцена Canvas не интерактивна. Симуляции подтверждают работоспособность экономики, но не заменяют тесты с живыми игроками.

Три следующих улучшения:

1. Контракты от конкретных приключенцев с наградами и сроками — больше планирования между днями.
2. Прогноз завтрашних событий с неполной достоверностью — осмысленный риск закупок впрок.
3. Постоянные клиенты с личными предпочтениями и доверием — повод думать о репутации и ценах на несколько дней вперёд.
